# Re-explain the Previous Response

Stop the current explanation. Re-pitch the previous response instead of continuing from it.

1. State the objective and the current point in the work.
2. Add only the earlier context needed to understand that point.
3. Use short sentences and Simplified Technical English principles.
4. Reuse established project terms from active instructions, documentation, and code. Do not require a specific context file.
5. Preserve material constraints, evidence, uncertainty, and warnings from the original response.
6. Explain necessary technical terms when the repository does not define them.
7. Do not continue the task or introduce a new plan unless the user asks.

Use headings or bullets only when they make the explanation easier to follow. Ask one focused question only when the missing context prevents an accurate explanation.

Before sending, confirm that the response can stand alone, uses consistent project terminology, and answers what the user did not understand.
